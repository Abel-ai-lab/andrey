## How we compare

**The same work.** Andrey 0.9.0 and Andrey 0.8.0 are two contestants in the benchmark harness, 0.8.0
installed from its release in a separate environment. Both fit the same datasets with the same
parameters and limits.

**The same machine, at the same time.** Each pair of fits runs in the same job on the same node,
on 4 CPUs with one BLAS thread, and with one worker unless a table says otherwise. TODO(<CPU>):
the CPU, named once; every row in a table ran on it.

**The same output.** A speedup counts only when both builds return the same output. We check this
by a hash of the full output of every fit. TODO(identity): the counts.

**The speedup.** Each size's speedup is 0.8.0's median time divided by 0.9.0's, over the size's
datasets. TODO(numbers): the rounds and warm-up fits per size.

**Data.** TODO(numbers): the regimes, sizes (variables, rows, mean degree), and datasets per size,

## Other changes in 0.9.0

- With more than one worker, `pc`, `fci`, `gfci`, and `cdnod` run the larger passes of their
  skeleton search in worker processes, with the same graphs and p-values as with one.
- `andrey calibrate --method skeleton` measures when a skeleton pass is large enough to repay the
  workers on your machine; `ANDREY_SKELETON_PARALLEL_MIN_WORK` sets it.
- `pnl` runs its independence tests on a CUDA GPU, in float64, from `ANDREY_PNL_GPU_THRESHOLD`.

The [changelog](../changelog.md) lists every change.

## Limits

- **Same output.** On the identity datasets, 0.9.0 returns exactly 0.8.0's outputs, the LiNGAM
  methods included. DirectLiNGAM, MultiGroupDirectLiNGAM, and the temporal LiNGAM methods compute
  their internal scores differently in the last bits, which could change a causal order only at an
  exact tie between two candidates. PNL's result can differ in the last digits between one worker
  and several.
- **Hardware.** Speedups are specific to the measured CPU, core budget, and settings. Worker
  processes repay their start-up cost only on large passes.
