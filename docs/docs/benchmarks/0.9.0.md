::::{div} release-opening-text

0.9.0 changes how fast Andrey runs, not what it returns. This card answers two questions. How much
faster is each method than in 0.8.0, on the same data with the same output? And where do the
headline comparisons with other packages stand on the 0.9.0 build? These results apply to the
measured workloads. Speed depends on the data, settings, and hardware.

## Summary

**Faster than 0.8.0, with the same output.** At the best of the sizes we measured, with one worker:
BOSS 8.19x, exact search 5.29x, GRaSP 3.89x, GFCI 3.18x, FCI 3.15x, LPCMCI 2.87x, PNL 2.28x,
MultiGroupDirectLiNGAM 1.97x, DirectLiNGAM 1.96x, PC 1.89x, GES and XGES 1.71x, CD-NOD 1.62x, and
LongitudinalLiNGAM 1.34x. With four workers, CD-NOD runs 4.62x faster than 0.8.0 and PC 2.60x.
Every fit of both builds returned the same output.

**No measurable change.** The other methods run as fast as in 0.8.0: their speedups lie within the
run-to-run spread, 0.85x to 1.24x.

## How we compare

**The same work.** Andrey 0.9.0 (release/0.9.0 at b94e647) and Andrey 0.8.0 (andrey-core 0.8.0 from
PyPI, with the same dependency versions) are two contestants in the benchmark harness. Both fit the
same datasets with the same parameters and limits: a 1,800 s wall cap and a 20,000 MB memory cap
per fit. No fit reached either.

**The same machine, at the same time.** Both builds of a row run in one job on one node, an AMD EPYC
7713, in a 4-CPU slot of a shared node. Each dataset is fit by one build and then the other, the
order swapped on alternate rounds, each fit in its own process. A one-worker fit runs on one thread;
a four-worker fit on 4 cores.

**The same output.** A speedup counts only when both builds return the same output. We check this by
a hash of the full output of every fit. Before the timing, the identity check compared the two
builds' full outputs on its own datasets: 1,216 of 1,216 rows identical (27 methods, five column
orders, one and four workers).

**The speedup.** A dataset's time is its median over 2 or 3 rounds, after 0 or 1 untimed warm-up
fit; a size's time is the median over its 3 or 5 datasets; the speedup is 0.8.0's time divided by
0.9.0's. Times and ratios have three significant figures.

**Data.** Each method runs on the data its release card used: linear-Gaussian Erdos-Renyi graphs
with mean degree 2 for most searches, and the family's own data for the latent-variable, pairwise,
multi-domain, and time-series methods. For the time-series methods, Variables counts the series and
Rows the time steps.

## Other changes in 0.9.0

- With more than one worker, `pc`, `fci`, `gfci`, and `cdnod` run the larger passes of their
  skeleton search in worker processes, with the same graphs and p-values as with one.
- `andrey calibrate --method skeleton` measures when a skeleton pass is large enough to repay the
  workers on your machine; `ANDREY_SKELETON_PARALLEL_MIN_WORK` sets it.
- `pnl` runs its independence tests on a CUDA GPU, in float64, from `ANDREY_PNL_GPU_THRESHOLD`.

The [changelog](../changelog.md) lists every change.

## Limits

- **Same output.** On the identity datasets, 0.9.0 returns exactly 0.8.0's outputs, the LiNGAM
  methods included. DirectLiNGAM, MultiGroupDirectLiNGAM, and the temporal LiNGAM methods compute
  their internal scores differently in the last bits, which could change a causal order only at an
  exact tie between two candidates. With one worker, PNL's linear algebra uses every core, so its
  result can differ in the last digits from that with several workers; the identity check pins one
  thread and cannot show it.
- **Hardware.** Speedups are specific to the measured CPU, an AMD EPYC 7713, the core budget, and
  the settings. Worker processes repay their start-up cost only on large passes.
- **Not faster everywhere.** The methods under [No measurable change](#no-measurable-change) run as
  fast as in 0.8.0, within the run-to-run spread.

## Reproduce

You can find environment setup, campaign drivers, and scores in the [benchmark harness
guide][harness]. To rerun a row, install Andrey 0.8.0 (andrey-core 0.8.0) in its own environment as
the guide's "Older Andrey builds" describes, and run the row's driver with both builds:
`anm_pairs.py`, `benchmark.py`, `boss_grasp_cpu.py`, `calm_cpu.py`, `cdnod_cpu.py`,
`confounded_cpu.py`, `exact_cpu.py`, `fci_latent.py`, `ges_cpu.py`, `gfci_latent.py`, `gies_cpu.py`,
`gin_cpu.py`, `granger_var.py`, `lingam_cpu.py`, `lingam_ts.py`, `multi_group_cpu.py`,
`pcmci_cpu.py`, `pnl_pairs.py`, `tabu_cpu.py`, and `xges_cpu.py`. The [summary][summary] names each
row's driver, solutions, and seeds. Times will differ with the hardware; outputs should match
exactly.
