## Where the time went

A causal discovery method spends its time on three jobs: tests or scores, the bookkeeping of the
graph it searches, and the memory that holds them. The
[Why Andrey is fast](20261008-why-andrey-is-fast.md) post shows the ideas we started from. 0.9.0
applies them further, without changing a single result.

**Ask in stacks.** PC, FCI, GFCI, and CD-NOD test whether two variables are independent given a
set of others. 0.9.0 hands the test all of a pair's conditioning sets at once, together with
those of the pairs next to it, so one array operation answers what took many. Exact search does
the same for its scores: it solves the equations of up to 4,096 parent sets in one call.

**Use every core.** With more than one worker, the largest passes of the PC, FCI, GFCI, and CD-NOD
skeleton search run in worker processes. Small passes stay in one process, where starting
workers would cost more than it saves. `andrey calibrate` measures that cutoff on your machine.

**Copy less.** A search tries many changes to its graph and keeps few. XGES now copies only the
part of the graph a branch changes. After each move, GES updates only the edges the move can reach
instead of rebuilding the whole graph, and keeps each reach set until a move can change it. BOSS
and GRaSP keep one tuple of candidate parents, and the set of allowed parents, instead of building
them again on every step.

**Build once.** FCI computes one reach set per variable for its possible-d-separation step, and
builds its neighbor lists and reach sets once for each version of the graph; GFCI builds each
node's neighbor list once. LPCMCI keeps each node's neighbors and paths for each version of the
graph instead of building them for every query. Exact search looks up each variable's best parent
set in a table built once per fit. DirectLiNGAM and the methods built on it compute each pair's
residual entropy once per step instead of twice. PNL builds each variable's kernel once and can run
its independence tests on a CUDA GPU.

**Hold less.** The first pass of PC, FCI, GFCI, and CD-NOD builds its queries one stack at a time
instead of listing every pair's conditioning sets first, which on a complete graph of 1,000
variables held gigabytes. ANM and the KCI test build their kernels in blocks, in one reused matrix.

## Limits

- **Measured speedups.** A speedup depends on the data, the settings, and the machine. Methods
  without speed work in 0.9.0 run as fast as in 0.8.0; the release card names them.
- **Same answers.** In the identity checks, the LiNGAM methods return 0.8.0's output exactly.
  Their internal scores can differ in the last bits, which could change a causal order only at an
  exact tie between two candidates. With one worker, PNL lets its linear algebra use every core, so
  on a machine with several cores its result can differ in the last digits from that with several
  workers.
- **Workers.** Worker processes repay their start-up cost only on large passes. On a small
  problem, one worker is as fast.
