# Nonlinear dependence

A constraint-based method learns a graph from independence tests. It is only as good as its test.
The default test, partial correlation, sees linear dependence only: when an effect bends, it can
miss an edge or add a false one. In 0.8.0, PC, FCI, GFCI, and CD-NOD take four supported tests that
detect nonlinear dependence: KCI, RCoT, CMIknn, and GPDC. Each makes fewer errors than the package
we measured it against, and runs faster at every size we timed: PC with RCoT runs more than 5x
faster than causal-learn and more than 9x faster than pcalg.

## TL;DR

- Four supported nonlinear tests: `indep_test="kci"`, `"rcot"`, `"cmiknn"`, and `"gpdc"`, in `pc`,
  `fci`, `gfci`, and `cdnod`.
- Fewer errors than the reference package, on average: 0.22 fewer per graph for KCI, up to 5.03
  fewer for RCoT against pcalg.
- Faster than the reference package at every size we timed: PC with RCoT runs 5.9x to 36x faster
  than causal-learn and 9.5x to 29x faster than pcalg.
- KCI and CMIknn also run on a CUDA GPU, with the same graphs as on the CPU.

## What partial correlation misses

Partial correlation asks whether `y` rises or falls with `x` in a straight line. Many effects do
not: a dose helps up to a point and then harms, a signal repeats, a cost grows with the square of a
size. Each panel below has 400 points with the same noise.

```{raw} html
:file: 0.8.0/dependence.html
```

On the line, both tests see the dependence. On the cos and the square, `y` clearly depends on `x`,
yet the straight-line trend is flat, so partial correlation finds nothing. KCI compares the two
variables through kernels, which respond to any shape of dependence, and finds all three.

## Four tests

Each test asks whether `x` and `y` are independent given a set of variables `z`. They differ in how
they measure dependence and in what they cost.

| `indep_test` | Test | How it decides | Cost |
|---|---|---|---|
| `"kci"` | Kernel conditional independence ([Zhang et al., 2011](https://arxiv.org/abs/1202.3775)) | Compares `x` and `y` in a Gaussian-kernel feature space after removing `z` | Grows with the square of the rows or faster; `rank=k` caps each kernel at `k` columns |
| `"rcot"` | Randomized conditional correlation ([Strobl, Zhang, and Visweswaran, 2019](https://arxiv.org/abs/1702.03877)) | Approximates the kernel test with quasi-Monte Carlo random Fourier features, sampled for each conditioning set | Linear in the rows; warns below 500 rows |
| `"cmiknn"` | Nearest-neighbor conditional mutual information ([Runge, 2018](https://proceedings.mlr.press/v84/runge18a.html)) | Estimates conditional mutual information and builds its null by shuffling `x` among neighbors in `z` | 500 shuffles per test by default |
| `"gpdc"` | Gaussian-process distance correlation ([Runge et al., 2019](https://doi.org/10.1126/sciadv.aau4996)) | Regresses `x` and `y` on `z` with Gaussian processes, then tests the residuals with distance correlation | Grows with the cube of the rows per regression |

Which to pick depends on the size of your data:

- **RCoT** costs time linear in the rows, and every fit we ran finished, up to 50 variables and
  5,000 rows. It warns below 500 rows.
- **KCI** we measured up to 20 variables at 2,000 rows. For more rows, `KCI(rank=...)` caps its
  cost, and a GPU runs it faster.
- **CMIknn** is the slowest of the four: 10 variables at 500 rows takes minutes.
- **GPDC** we measured up to 20 variables at 1,000 rows. Its cost grows with the cube of the rows.

## How fast, and how accurate

We compared PC and FCI with each test against the package that implements it: causal-learn for
KCI and RCoT, pcalg with RCIT for RCoT, and tigramite for CMIknn and GPDC. Each ran on additive
data and on nonmonotone data, through `cos`, with 20 datasets per size, and we timed 5 of them.

```{raw} html
:file: 0.8.0/comparison.html
```

On nonmonotone data, partial correlation makes more errors than the empty graph from 10 variables
on, and every test stays below it, in Andrey and in each reference package.

KCI and CMIknn also run on a CUDA GPU (`ANDREY_BACKEND=cuda`) and return the same graph as on the
CPU; the [0.8.0 release card](../docs/benchmarks/0.8.0.md) lists the speedups and the hardware.

## Limits

- **Measured sizes.** PC up to 20 variables at 2,000 rows with KCI, 50 variables at 5,000 rows
  with RCoT, 20 variables at 500 rows with CMIknn, and 20 variables at 1,000 rows with GPDC. FCI
  with KCI and RCoT at 5 and 10 variables. The release card lists every size and the hardware.
- **Cost.** KCI and GPDC grow fast with the rows; `KCI(rank=...)` caps KCI's cost. CMIknn grows
  with the variables and the rows.

0.8.0 also brings background knowledge for every search, score defaults that follow the data, and
faster categorical tests. The [0.8.0 release card](../docs/benchmarks/0.8.0.md) and the
[changelog](../docs/changelog.md) give the details.
